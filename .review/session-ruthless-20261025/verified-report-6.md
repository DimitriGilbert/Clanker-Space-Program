### Finding 1: Poisoned template permanently wedges every future step_frame — CONFIRMED
**Original**: offer_index advances only after a successful draw, so a deterministic Recoverable from generate_offer recurs forever; doc claims the publish merely "degrades".
**Verification**: contracts.rs:712-721 — `let Some(offer) = self.generate_offer(index)? else { break; }` returns BEFORE `self.contracts.offer_index = index.checked_add(1)`; the index is re-read at loop top, so the retry re-draws the identical index. generate_offer is deterministic: RNG stream keyed only by `(save_seed, StreamKey{Contracts, entity:0, counter:index})` (contracts.rs:673-680); eligible set derives from `contract_defs` (mutated only by `set_contracts`, contracts.rs:618-620, which installs raw defs with no validation) and facts (rolled back). Failure paths are real: `draw_params` returns Recoverable on empty body/experiment/module/resource spaces and on `!params_ok` (contracts.rs:281-390). Propagation: lib.rs:6694 `self.publish_contracts(shadow)?` inside `advance_interval_subsystems`; lib.rs:7565-7574 `shadow.restore(self); return Err(e)`. Restore reverts the contracts slot: `publish_contracts` calls `shadow_contracts(shadow)` BEFORE the loop (contracts.rs:711, capture at 586-590), and `TickShadow::restore` writes `world.contracts = captured` — so offers stays short of board_size, offer_index reverts to the failing index, and the next step_frame re-fails identically. The crate's own test `empty_bodies_space_rejects_recoverable` (contracts.rs:1570-1588) pins exactly this: one poisoned template → `step_frame` returns Recoverable. The `degraded: &mut Vec<SimError>` channel exists in `advance_interval_subsystems` (lib.rs:6652, used by `advance_orbits` at 6657) but this path ignores it. Severity MEDIUM stands (requires an unvalidated `set_contracts` install — the RON path is validator-gated), but impact wording is accurate: world is permanently immobile.

### Finding 2: Instant-completion faucet unbounded (infinite offer indexes, no active cap) — CONFIRMED

**Verification**: contracts.rs:810-813 — `if self.objective_met(&self.contracts.active[&id].params, None) { self.complete_contract(id, shadow)?; }` evaluates on CURRENT state at accept. ColonyResupply sums cumulative `facts.colony_deliveries` (contracts.rs:880-899), SurveyData reads cumulative returned units (846-850), SatelliteOrbit/PartTest read any current vessel (831-869). `colony_deliveries` is write-only monotone: `+= landed` at transfers.rs:1034-1041, no decrement anywhere (all 8 usages reviewed). Payouts: advance credited at contracts.rs:805-809, completion at 1033 via `credit_funds` (economy.rs:669-680 — no cap, nothing limits repeat credit; independent re-check of the verify-C7 claim holds). Board refill: publish_contracts (contracts.rs:705-723) runs at every interval advance while `offers.len() < board_size`, advancing offer_index without bound (u64 counter, 717-720); in step_frame the boundary drain that applies AcceptContract (lib.rs:7527) precedes advance_interval_subsystems (lib.rs:7566), so the board refills with a fresh index in the SAME step_frame — one command per payout. `contracts.active` insertion at 796 is uncapped (no MAX_ACTIVE/cap anywhere; grep confirms only test assertions). facts.completed stamps at 1017-1022, so ContractsCompleted prereqs inflate freely. Doc at contracts.rs:747-749 ("once per offer index") is accurate per-index but the index supply is infinite — the bounded reading is false. MEDIUM (documented v1 semantics) stands.

### Finding 3: Converter output into zero-capacity resource silently voided — CONFIRMED
**Original**: converter whose recipe outputs a resource with no store module runs at fraction 1.0, drains inputs, and the output ceases to exist — no event, no rejection, no clamp.
**Verification**: Store entries exist ONLY for `Store`/`Battery` modules and `def.stores` rows (colonies.rs:1581-1608, 1609-1620). The solve is input-side only: `grounded_modules` checks each module's REQUESTED resources against stock/other-module outputs (colonies.rs:784-787); fractions derive from input grants (873-878); nothing inspects output headroom. `module_productions` returns converter recipe outputs unconditionally (685-695), so `net_rates[out] = produced − consumed` is computed (1013-1018) — but the write-back loop `for (r, s) in colony.stores.iter_mut()` (colonies.rs:2277-2279) touches only existing store entries: a resource with no store has no level anywhere (`level_at` is a ColonyStore method, 275-283) and its produced rate is dropped. Inputs ARE charged: `consumed` at 1004-1012 feeds the input store's negative net_rate, draining it. No signal: `earliest_store_bound` (1146-1175) and the `ColonyStoreFull/Empty` events iterate `colony.stores` only; `module_fractions[i]` is written as 1.0 on the colony (2275). No gate anywhere: sim-side `colony_def_fields_finite` (1405-1441) only requires the recipe to resolve with finite rates (the explicit unknown-recipe rejection at 1428 shows the module's own "reject, never silently inert" discipline); data-side `validate_colonies` (csp-data/src/validate.rs:2064-2276) checks converter recipe known + power finite, never that outputs have storage. A def with Converter(ore→metal) + ore Store and no metal Store founds cleanly and destroys ore forever. MEDIUM stands.

### Finding 4: Abandon salvage silently discarded when the site has no economy record — CONFIRMED

**Verification**: colonies.rs:1684-1688 — the `if let Some` skips the entire salvage loop; execution continues to crew reassignment (1689-1695), `state = Abandoned` (1700), store freeze (1706-1712), event drop (1713), `Ok(())`. One-way terminal command + silent destruction of the player's recovered resources. LOW stands.

### Finding 5: Founding store levels silently clamped; duplicate init rows silently overwrite — CONFIRMED (with reachability nuance)

**Verification**: colonies.rs:1609-1620 — level validation is only `s.level.is_finite() && s.level >= 0.0` (1610-1612), then `store.anchor_level = s.level.min(store.capacity)` (1619) — an authored 1000 into a 100-unit store founds at 100 silently, unlike the neighboring typed Recoverables ("bad store level"/"bad store capacity" at 1611/1623) and the unknown-recipe rejection (1428). LOW stands.

### Finding 6: body_light silently fabricates a fixed sun on orbit-model miss — CONFIRMED
**Original**: `orbits.body_orbit(body).ok()` swallows the lookup error and defaults to `(n = 0, L0 = 0)`, freezing the sun in inertial space for a body missing from the orbit model.
**Verification**: colonies.rs:416-420 — `orbits.body_orbit(body).ok().and_then(|o| o.elements.as_ref()).map_or((0.0, 0.0), ...)`; the doc (405-408) explicitly blesses the default ("the star itself") but nothing distinguishes a star from an ordinary body with a missing record. With `rotation_period_s: None` (tidally locked): `omega = n = 0` → `synodic_rate = 0` (436), `hour_angle` constant (444-447), permanent Daylight/Night, `next_terminator_tick` returns None (comment at 469-470), solar output constant forever. `apply_found_colony` checks `colony_env` presence (colonies.rs:1555-1559) but never cross-checks `body_orbit` — an env/orbit table disagreement produces a silently wrong power model with no diagnostic. LOW stands.
